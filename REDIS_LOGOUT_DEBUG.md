# Диагностика проблемы с сохранением JWT токенов в Redis при logout

## Проблема
JWT токен не сохраняется в Redis при выходе пользователя (logout).

## Возможные причины

### 1. Redis не запущен
**Проверка:**
```bash
# Проверить, запущен ли Redis
redis-cli ping
# Должен вернуть: PONG
```

**Решение:**
```bash
# Запустить Redis через Docker
docker-compose up -d redis

# Или локально
redis-server
```

### 2. Неправильные настройки подключения
**Проверка:** Файл `application.yml`:
```yaml
spring:
  data:
    redis:
      host: localhost
      port: 6379
      password:  # Должно быть пустым, если пароль не установлен
```

### 3. Ошибка при сохранении (проверьте логи)
**Что искать в логах:**
- `Ошибка при добавлении токена в blacklist`
- `Redis недоступен`
- `Ошибка подключения к Redis`
- `Токен не был сохранен в Redis`

### 4. TTL токена истек или отрицательный
Если токен уже истек, TTL может быть отрицательным, и ключ не сохранится.

## Улучшения в коде

### Добавлено:
1. **Детальное логирование** - теперь логируются:
   - Ключ Redis
   - Первые 20 символов токена
   - TTL в миллисекундах и минутах
   - Результат проверки сохранения

2. **Проверка подключения к Redis** перед сохранением

3. **Проверка успешности сохранения** - после сохранения проверяется, что значение действительно записалось

4. **Улучшенная обработка ошибок** с детальным логированием стека

## Как проверить, что токен сохранился

### 1. Через Redis CLI
```bash
redis-cli

# Получить все ключи blacklist
KEYS jwt:blacklist:*

# Получить значение по ключу
GET jwt:blacklist:{hashCode}

# Проверить TTL
TTL jwt:blacklist:{hashCode}
```

### 2. Через API
```bash
# Получить все токены из blacklist
GET /api/admin/blacklist/keys
Authorization: Bearer {admin_token}

# Проверить конкретный токен
POST /api/admin/blacklist/check
{
  "token": "your_jwt_token_here"
}
```

### 3. Через логи приложения
Ищите в логах:
```
Токен успешно добавлен в blacklist. Ключ: jwt:blacklist:123456789, TTL: 86400000 ms
```

## Шаги для диагностики

1. **Проверьте, запущен ли Redis:**
   ```bash
   redis-cli ping
   ```

2. **Проверьте логи приложения** при выполнении logout:
   - Должны быть сообщения о попытке сохранения
   - Должны быть сообщения об успехе или ошибке

3. **Проверьте подключение к Redis:**
   ```bash
   # В логах должно быть:
   "Подключение к Redis успешно"
   ```

4. **Проверьте, что токен действительно сохранился:**
   ```bash
   redis-cli
   > KEYS jwt:blacklist:*
   > GET jwt:blacklist:{hashCode}
   ```

5. **Проверьте настройки в application.yml:**
   - `spring.data.redis.host`
   - `spring.data.redis.port`
   - `spring.data.redis.password`

## Новые методы для диагностики

В `TokenBlacklistService` добавлены методы:

1. `isRedisAvailable()` - проверка доступности Redis
2. `testRedisConnection()` - тестовое сохранение/чтение для проверки подключения

## Типичные ошибки

### Ошибка: "Redis недоступен"
**Причина:** Redis сервер не запущен или недоступен по указанному адресу/порту
**Решение:** Запустите Redis и проверьте настройки подключения

### Ошибка: "Токен не был сохранен в Redis"
**Причина:** Операция set() не выполнилась успешно
**Решение:** Проверьте права доступа к Redis и логи для деталей

### Ошибка: "Connection refused"
**Причина:** Redis не слушает на указанном порту
**Решение:** Проверьте, что Redis запущен и слушает на порту 6379

## Логирование

Теперь в логах вы увидите:
```
DEBUG: Добавление токена в blacklist. Ключ: jwt:blacklist:123456789, Токен (первые 20 символов): eyJhbGciOiJIUzI1NiIs...
DEBUG: Подключение к Redis успешно
DEBUG: TTL токена: 86400000 ms (1440 минут)
INFO: Токен успешно добавлен в blacklist. Ключ: jwt:blacklist:123456789, TTL: 86400000 ms
```

Если есть ошибки:
```
ERROR: Ошибка при добавлении токена в blacklist: Connection refused
ERROR: Стек ошибки: java.net.ConnectException: Connection refused
```

---

**Важно:** После этих изменений проверьте логи при выполнении logout. Если проблема сохраняется, логи покажут точную причину.
