# AsyncGoService

Асинхронный HTTP-сервис на языке Go, демонстрирующий использование горутин, каналов и пула воркеров для обработки задач.

## Описание

Сервис реализует асинхронную обработку задач с использованием:
- **Горутин (Goroutines)** - для параллельной обработки запросов
- **Каналов (Channels)** - для безопасной передачи данных между горутинами
- **Worker Pool** - пул воркеров для обработки задач из очереди
- **REST API** - HTTP endpoints для управления задачами

## Функциональность

### Основные компоненты

1. **TaskService** - сервис управления задачами
   - Очередь задач (канал)
   - Пул воркеров для обработки
   - Хранение состояния задач

2. **Task** - структура задачи
   - ID, тип, данные
   - Статус (pending, processing, completed)
   - Результат выполнения

### API Endpoints

#### `GET /`
Информация о сервисе

#### `POST /api/tasks`
Создание новой задачи
```json
{
  "type": "calculate",
  "data": "some data to process"
}
```

#### `GET /api/tasks`
Получить все задачи

#### `GET /api/tasks?id=<task_id>`
Получить задачу по ID

#### `GET /api/health`
Проверка здоровья сервиса (статус, количество воркеров, размер очереди)

## Установка и запуск

### Требования
- Go 1.21 или выше

### Запуск

1. Перейдите в директорию проекта:
```bash
cd AsyncGoService
```

2. Установите зависимости (если есть):
```bash
go mod tidy
```

3. Запустите сервер:
```bash
go run main.go
```

Сервер запустится на порту `8081` (по умолчанию).

### Переменные окружения

- `MAIN_SERVICE_URL` - URL основного сервиса для отправки результатов (по умолчанию: `http://localhost:8080`)
- `ASYNC_TOKEN` - Токен авторизации для отправки результатов в основной сервис (по умолчанию: `async123`)

Пример запуска с переменными окружения:
```bash
MAIN_SERVICE_URL=http://localhost:8080 ASYNC_TOKEN=async123 go run main.go
```

## Примеры использования

## Архитектура

### Асинхронная обработка

1. Клиент отправляет POST запрос на создание задачи
2. Задача добавляется в очередь (канал)
3. Сервер сразу возвращает ответ клиенту (не дожидаясь выполнения)
4. Воркер из пула забирает задачу из очереди
5. Задача обрабатывается асинхронно
6. Статус задачи обновляется (pending → processing → completed)

### Пул воркеров

- По умолчанию: 3 воркера
- Размер очереди: 100 задач
- Каждый воркер работает в отдельной горутине
- Graceful shutdown при получении сигнала

## Интеграция с основным сервисом

Сервис может автоматически отправлять результаты обработки задач обратно в основной сервис через HTTP.

### Формат данных задачи

Для отправки результатов в основной сервис, данные задачи должны содержать `calcOrderId` и `gasId` в формате:
```
calcOrderId:gasId
```

Например: `1:5` означает заявку с ID 1 и газ с ID 5.

### Автоматическая отправка результатов

После обработки задачи, если указан `MAIN_SERVICE_URL`, сервис автоматически отправляет результат в основной сервис на endpoint:
```
POST /api/gas-orders/async-results
```

С заголовком авторизации:
```
X-Async-Token: async123
```

## Особенности реализации

- **Thread-safe**: использование `sync.RWMutex` для безопасного доступа к данным
- **Graceful shutdown**: корректное завершение работы при получении сигнала
- **Асинхронность**: клиент не ждет завершения обработки задачи
- **Масштабируемость**: легко изменить количество воркеров и размер очереди
- **Интеграция**: автоматическая отправка результатов в основной сервис

## Типы задач

Поддерживаемые типы задач:
- `calculate` - вычисления
- `process` - обработка данных
- `transform` - преобразование данных
- Любой другой тип - общая обработка
